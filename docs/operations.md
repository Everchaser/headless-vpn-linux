# Эксплуатация

Запускай административный CLI из root-owned каталога `/opt/headless-vpn` от пользователя `headless-vpn`, не от root.

```bash
cd /opt/headless-vpn
sudo -u headless-vpn /usr/bin/python3 -m headless_vpn.cli subscription list
sudo -u headless-vpn /usr/bin/python3 -m headless_vpn.cli check
sudo -u headless-vpn /usr/bin/python3 -m headless_vpn.cli probe
```

`subscription add NAME [--device-name LABEL]` добавляет новый источник; `subscription remove NAME` удаляет его из следующего поколения, а не отзывает регистрацию в кабинете провайдера. `subscription refresh` перечитывает известные ссылки; у источников, не прошедших проверку, остаются прежние узлы. `list` показывает обезличенные ID и источники. `init` и `add` умеют импортировать совместимый локальный Xray JSON. Команды `subscription add`, `add` и успешный `refresh` публикуют поколение: наблюдатель может сменить дочерний Xray и на несколько секунд оборвать текущие соединения. Их нельзя считать read-only.

Управляемое обновление при запущенном TUN: `sudo systemctl start headless-vpn-refresh.service`. Таймер работает примерно раз в час; `Requisite=` не запускает остановленные службы. Штатный выбор узла проверяет доступность и задержку, отсутствие доступных узлов не означает разрешение идти напрямую из Xray.

| Симптом | Что проверять |
|---|---|
| `ok: false` после чтения ссылки | Подписка разобрана, узел не прошёл пробу. Если нужен HWID и регистрация разрешена, используй `--device-name`. Не подменяй живую конфигурацию непроверенным узлом. |
| `Prepared … nodes` | Публикация прошла. Проверь `Generation applied` и контрольный HTTPS. Это не число отвечающих в данный момент узлов. |
| Сервисы `active`, но трафик не идёт | Раздельно проверь TUN и `--proxy socks5h://127.0.0.1:10818`, DNS и TCP/TLS. Один ответ IP-чекера или разовый TLS EOF не доказывает падение. |
| Таймер сообщает `dependency` | Проверь обе службы. При выключенном Headless ожидаемо, таймер их не включает. |
| Xray не восстанавливается после смены поколения | Сверь время публикации, `NRestarts`, сообщение `Generation applied`. Проверь доступ к проверяемому HTTPS-ресурсу и bootstrap DNS на физическом IPv4; не отключай TLS-проверку. |

```bash
systemctl show headless-vpn.service headless-vpn-xray.service -p MainPID -p NRestarts
journalctl -b -u headless-vpn-xray.service --no-pager -n 30
```

Журналы TUN могут содержать посещаемые домены и адреса. Для сторонней диагностики передавай только время, безопасные сообщения о состоянии и статусы запросов, а не сырые логи. Резервный state содержит bearer-ссылки и доступы: резервируй его отдельно и зашифрованно, не включай в Git. Установщик рассчитан на первичную установку; не запускай `--stage` для обновления кода и не подменяй живые файлы. Сначала тестируй новую версию на отдельной VM. Обновление установленного кода, возвращение прежнего ядра и холодный старт — отдельные операции.

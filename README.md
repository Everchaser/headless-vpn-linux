# Headless VPN v2

VPN-клиент для Linux-сервера без графического входа. `sing-box` поднимает системный TUN; отдельный непривилегированный Xray выбирает доступный узел и принимает трафик только на `127.0.0.1:10818`. Подписки могут требовать HWID. Проверенные обновления подхватываются автоматически: процесс Xray может кратко переподключить клиента, но штатное обновление не перезапускает TUN.

```
приложения → tun0 (sing-box) → SOCKS на loopback → Xray → VPN-узел
                              Xray → loopback DNS → TLS/IPv4 → 1.1.1.1:443
```

Последняя ветка разрешает **только имена настроенных VPN-узлов**: это устраняет зависимость запуска Xray от DNS внутри уже работающего VPN. DNS обычных приложений остаётся в туннеле.

## Начало работы

Нужны Linux с systemd, Python 3.10+, `/dev/net/tun`, физический IPv4-маршрут, Bash, curl, iproute2, системные CA и права администратора. Этот профиль **только для IPv4**: установщик активации откажется при IPv6 default route в основной таблице; наличие альтернативных IPv6/политических маршрутов проверяет оператор. Начинай с чистого сервера или VM, где есть локальная/провайдерская консоль. TUN может оборвать SSH. Docker, WSL, другие VPN и машины с несколькими uplink не входят в проверенный профиль.

1. Скачай и проверь ядра из [официальных релизов](docs/upstream.md), ничего не запускай из сети от root.
2. Выполни [установку на чистый сервер](docs/deploy.md): подготовка → ввод подписки → `check`/`probe` → отдельная активация → проверка и откат.
3. Для дальнейшей работы используй [эксплуатацию и диагностику](docs/operations.md).
4. Агентам: читать [AGENTS.md](AGENTS.md) и [SKILL.md](SKILL.md). Скилл не устанавливает приложение и не разрешает менять маршруты сам по себе.

## Тесты без изменения сети хоста

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -q
# Дополнительно: два локальных тестовых upstream, реальное ядро Xray, без TUN.
HEADLESS_XRAY=/absolute/path/to/xray python3 tests/integration_failover.py
```

Здесь только код, systemd-юниты, шаблон и тестовые данные. Рабочие URLs, экспорт провайдера, HWID, каталог узлов и закрытые ключи остаются на целевом сервере. Бинарники не включены. Исходная версия проверена на рабочем сервере, но этот установщик требует отдельной проверки на новой машине; результаты модульных и loopback-тестов не доказывают загрузку или SSH-доступность. См. [чек-лист приёмки](docs/checklist.md).
